# ADR-0004: RAG-Architektur – Chunking, Modell und Hybrid-Suche

Datum: 2026-09-12 · Status: akzeptiert

## Kontext

Der MCP-Server `maintenance_docs` stellt Wartungswissen (Anleitungen, Fehlercodes, Störungsberichte)
für den Agenten bereit. Für die Demo muss die Suche zwei Anforderungen erfüllen:

1. **Exakte Codes** (E-4711, W-1001 …) sollen präzise getroffen werden – Schlüsseleigenschaft für
   Alarmanalyse, weil der Produk­tions­leiter genau diesen Code nennt.
2. **Semantische Fragen** ohne genauen Code sollen relevante Abschnitte finden
   (z. B. „Warum steht die Siegelstation?").

Weiterhin muss das System lokal lauffähig und ohne Cloud-Schlüssel betreibbar sein (PoC-Umgebung).

## Chunking-Entscheidung

**Gewählt: absatzweises Chunking mit Überschrift-Präfix.**

Jeder Absatz (Split auf `\n\n`) wird ein eigener Chunk. Nicht-Überschrift-Absätze erhalten den
zuletzt gesehenen Abschnittsnamen als Präfix in der Form `[Abschnitt] Text`. Das sichert, dass ein
Chunk auch ohne Dokument-Kontext inhaltlich einordenbar ist.

Alternativen verworfen:
- **Fester Token-Fenster** (z. B. 256 Tokens mit Überlappung): Präzision bei exakten Codes
  schlechter, weil Codes in der Mitte eines Fensters landen können. Mehr Implementierungsaufwand.
- **Ein Chunk je Dokument**: Zu grob für Fehlercode-Lookup; bei 8 000-Zeichen-Limit werden Dokumente
  abgeschnitten.

## Modell-Entscheidung

**Gewählt: `intfloat/multilingual-e5-small`**

- Multilingual (Deutsch nativ), 117 MB, läuft auf CPU in < 200 ms/Batch.
- Empfehlung für hybride Suche mit kurzen Abschnitten aus dem E5-Paper
  (Wang et al. 2022, arXiv:2212.03533).
- Kein API-Schlüssel; Lizenz MIT.

Alternativen verworfen:
- **paraphrase-multilingual-MiniLM-L12-v2**: Vergleichbare Größe, aber E5-small übertrifft es auf
  deutschen Retrieval-Benchmarks (BEIR-DE).
- **text-embedding-3-small (OpenAI)**: Sehr gut, aber API-Schlüssel erforderlich → widerspricht
  Offline-Anforderung.
- **deepset/gelectra-base**: Gut für Deutsch, aber kein gutes multilinguales Modell für künftige
  Erweiterungen.

## Hybrid-Suche (BM25 + Vektor, RRF)

**Gewählt: Reciprocal Rank Fusion (k=60) mit BM25-Doppelgewichtung bei Alarmcodes.**

- BM25 (rank-bm25) trifft exakte Codes mit hoher Präzision.
- Vektorsuche (Qdrant lokal) findet semantisch ähnliche Abschnitte auch ohne exakten Code.
- RRF (Cormack et al. 2009) kombiniert beide Ranglisten ohne Score-Normalisierung.
- Erkennt Qdrant-Verbindungsfehler (kein Index vorhanden) und fällt auf BM25-only zurück.
- BM25 wird doppelt gewichtet, wenn der Query einen Code `[EWI]-\d{4}` enthält, weil in diesem
  Fall Präzision wichtiger ist als semantische Breite.

Alternativen verworfen:
- **Chroma (lokal)**: Einfacher, aber kein persistenter Disk-Index ohne Konfiguration; geringere
  Filterperformanz für große Sammlungen.
- **Azure AI Search (hybrid)**: Sehr gute Hybrid-Suche, aber Cloud-Abhängigkeit und monatliche
  Kosten – schließt Offline-Demo aus.
- **Weaviate / Milvus**: Produktionsreif, aber deutlich mehr Betriebsaufwand für einen PoC
  (eigener Prozess, Konfigurationsdateien).
- **Nur BM25**: Ausreichend für Codes, aber versagt bei paraphrasierten Fragen ohne Schlüsselwort.

## Optionen

Zusammengefasst aus den drei Teilentscheidungen oben:

- **Chunking:** absatzweise mit Überschrift-Präfix · festes Token-Fenster · ein Chunk je Dokument.
- **Embedding-Modell:** `multilingual-e5-small` · `paraphrase-multilingual-MiniLM-L12-v2` ·
  `text-embedding-3-small` (OpenAI) · `deepset/gelectra-base`.
- **Suche:** Hybrid BM25 + Vektor (RRF) · Chroma · Azure AI Search · Weaviate/Milvus · nur BM25.

## Entscheidung

- **Chunking:** absatzweise mit Überschrift-Präfix (`[Abschnitt] Text`).
- **Modell:** `intfloat/multilingual-e5-small` (Deutsch nativ, CPU, kein API-Schlüssel, MIT).
- **Suche:** Reciprocal Rank Fusion (k=60), BM25 bei erkanntem Alarmcode `[EWI]-\d{4}` doppelt gewichtet,
  Fallback auf BM25-only bei fehlendem Qdrant-Index.

Begründung und die jeweils verworfenen Alternativen stehen ausführlich in den drei Abschnitten oben.

## Konsequenzen

- `sentence-transformers` ist optional (`pip install 'production-agent[embeddings]'`); fehlt es,
  läuft der Server mit BM25-only ohne Fehler.
- `ingest_docs()` muss vor der ersten Vektorsuche aufgerufen werden
  (`python -m production_agent.mcp.rag_server --ingest`).
- Der Qdrant-Index liegt unter `data/qdrant/` (gitignored); CI läuft BM25-only.
- Dokumente in `data/docs/` sind simuliert und öffentlich; kein Personenbezug.
- Injection-Schutz: `sanitize_tool_result()` markiert Chunks mit instruktionsartigen Passagen
  mit `[WARNUNG]` und verhindert so Prompt-Injection über Dokument-Inhalte.
